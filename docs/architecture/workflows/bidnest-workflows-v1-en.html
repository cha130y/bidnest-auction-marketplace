Before the diagrams — context

What this system does, and what it is made of

One person is both buyer and seller on a single account. The only difference between the two modes is how the price gets decided.

Track A — Auction

The price is settled by competing bids

The seller schedules an auction, the system opens and closes it on time, buyers compete in a real-time room, and late bids extend the clock automatically. When time is up, the highest bidder wins.

Track B — Marketplace

The price is set, buy it now

The seller lists an item with stock and a price. Buyers fill one cart from several shops, negotiate with the AI if the seller allows it, then pay once.

00 — Overall

Whole-system overview: two ways to reach a price, one place to pay

The top row is the auction, the middle row is the buy-now marketplace. They differ only in how the price is reached — once there is a price, both walk exactly the same path.

01 — Identity

Sign up / sign in: always in two beats

Password or Google/LINE, it makes no difference: the first beat only proves who you are, and the token is issued after the second beat, the OTP — unless the device was ticked as remembered.

02 — Auction lifecycle

Auction lifecycle: the seller presses two buttons, the clock does the rest

The only buttons the seller presses are “publish” and “cancel”. Opening the auction at its start time, and closing it with a winner when time is up, are background work that sweeps every 10 seconds. While it is still ACTIVE, the end time can keep moving out from late bids.

03 — Place a bid

Placing a bid: check everything, write once, announce afterwards

Every check and the write itself live in one transaction, and the broadcast to the room always happens after the commit — because a price that has been announced cannot be taken back.

04 — Live arena

Live auction room: lobby → arena → closing window → result

Everything on screen — the leader, the time left, the urgency — is computed on the server side, with the same rules that decide the real winner.

05 — Watchlist & notifications

Watchlist and notifications: one event, two destinations

Every notification is written to the database first and only then pushed over WebSocket — so someone who had the tab closed still sees it afterwards, rather than a message that vanished with the connection.

06 — Product status

Product status: a seller pausing a listing and an admin suspending it are separate states

Sellers can pause their own listings whenever they like, and running out of stock flips the status automatically. But a product an admin suspends lands in a different state that the seller cannot lift — and cannot dodge by deleting the listing and posting it again either (ADR-0002).

07 — Cart & checkout

Cart → checkout: pay once, one order per seller

Prices are recomputed when you press pay rather than trusting the numbers sitting in the cart, and the payment record is written separately from the orders, so money that has moved always leaves a trace.

08 — Shipment

Shipment: forward only, cancellable only before it leaves the shop

The seller moves it one step at a time — no skipping, no going back. Every move is written as an event on the timeline the buyer sees, along with a notification.

09 — AI price estimate

AI price estimate: a suggestion, not the price itself

It only runs against your own auction draft, and what comes back is a number to consider — the seller is still the one who types the starting price.

10 — AI negotiation

AI negotiation: judged against the floor price the seller set

The seller records the lowest price they will accept on the product, and the AI has no authority to go below it — which leaves exactly three possible outcomes.

11 — Support chat

Support chat: the AI answers first, a human takes over when needed

There are two ways to hand off — the user asks for it, or the system sees the AI fail three times in a row. Once it is handed off the AI stops answering immediately; the room belongs to the admin.

12 — Buyer & seller chat

Buyer–seller chat: every room is tied to one product or one auction

There is no free-floating chat — you open one from an auction page or a product page, and only from there. Both sides then always know which item is being discussed, without asking each time.

13 — Admin action

Admin actions: every action needs a reason, and every one is recorded

Suspending a user, cancelling an auction, taking a product off sale — every action walks the same path. The status change and the log entry happen together in one transaction, and if either side fails, both fail. So a status can never change without a trace of who ordered it and why.

Reference — states

The state names worth memorising

These names are identical across the schema, the API and the UI — use them when talking to the team.

What States Who changes it
Auction DRAFT SCHEDULED ACTIVE SOLD UNSOLD CANCELLED Seller publishes / cancels · admin cancels · everything else is the timed background job
Product ACTIVE INACTIVE OUT_OF_STOCK REMOVED SUSPENDED The seller manages all of it except SUSPENDED, which only an admin sets and the seller cannot lift
Order PENDING PAID CANCELLED Set by the result of the charge at checkout
Shipment PROCESSING SHIPPED IN_TRANSIT DELIVERED CANCELLED The seller advances one step at a time; the buyer sees it as a timeline
Support chat AI_ONLY ESCALATED RESOLVED The user asks for a human, or the AI fails 3 times → an admin takes over
Reference — code owners

Who owns what

Talk to the owner before making a change across modules, especially in schema.prisma, which has a single owner.

Dev Scope Main code
Dev 1 Frontend & UI apps/web/src/components · design-system
Dev 2 Backend core & security — owns the schema and the migrations api/src/auth · users · common (guards)
Dev 3 E-commerce — products, cart, orders, shipping, buyer–seller chat api/src/product · cart · order · shipment · chat
Dev 4 Auction & real-time — auctions, bids, live room, watchlist api/src/auction · bid · live · realtime · watchlist
Dev 5 AI — price estimate, negotiation, support chat api/src/ai-tools · support-chat

V1 scope: the story ends when the auction closes and the item is delivered — there are no refunds or cancellations after that. SOLD and UNSOLD really are terminal, and payment is simulated: no real payment gateway is wired up yet.
