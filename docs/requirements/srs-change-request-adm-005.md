# SRS Change Request — ADM-005 บังคับใช้ไม่ได้ตามที่เขียนไว้

- **เสนอเมื่อ:** 2026-08-19
- **SRS ฉบับปัจจุบัน:** `BidNest-Auction and Marketplace-v4.pdf`
- **อ้างอิงการตัดสินใจ:** [ADR-0002](../architecture/adr/0002-admin-suspended-product-status.md)
- **สถานะ:** รอแก้ SRS (โค้ดและ schema แก้ไปแล้ว)

## ปัญหา

SRS v4 มีข้อกำหนด 2 ข้อที่ขัดกันเอง:

- **ADM-005** ให้ Admin ปิดการขายสินค้าที่ไม่เหมาะสมได้
- **PROD-002** ให้ผู้ขายแก้สถานะสินค้าของตัวเองระหว่าง `ACTIVE` และ `INACTIVE` ได้

เนื่องจาก `ProductStatus` เดิมมีแค่ `ACTIVE / INACTIVE / OUT_OF_STOCK / REMOVED` จึงแยกไม่ออกว่า `INACTIVE` เกิดจากผู้ขายปิดเองหรือ Admin สั่งปิด **ผลคือผู้ขายกด `ACTIVE` กลับได้ทันทีหลัง Admin สั่งปิด ทำให้ ADM-005 ไม่มีผลบังคับจริง**

ทีมตัดสินใจแล้วว่า **ถ้า Admin เป็นคนสั่งปิด ผู้ขายต้องเปิดกลับเองไม่ได้** และได้เพิ่มสถานะ `SUSPENDED` เข้า `ProductStatus` แล้ว (migration `20260819031110_add_suspended_product_status`)

เอกสารนี้รวบรวมข้อความที่ต้องแก้ใน SRS ให้ตรงกับสิ่งที่ implement ไปแล้ว

> **หมายเหตุ:** ข้อความ "เดิม" ด้านล่างถอดมาจาก PDF จึงอาจต่างจากไฟล์ต้นฉบับเล็กน้อยเรื่องเว้นวรรค ให้ค้นด้วยวลีที่ **ตัวหนา** เพื่อหาตำแหน่ง

## แก้ที่ 1 — ADM-005 (§4.8 การบริหารจัดการระบบ)

**เดิม**

> ADM-005 · ควบคุมดูแลรายการสินค้า · Admin ปิดหรือเปิดการขายสินค้าที่ไม่เหมาะสมกลับคืนได้ พร้อมบันทึกเหตุผลไว้ทุกครั้ง เหมือนกับ ADM-001 **การปิดการขายจะปิดกั้นคำสั่งซื้อใหม่ แต่ไม่ยกเลิกคำสั่งซื้อที่จ่ายเงินแล้ว (PAID)**

**ใหม่**

> ADM-005 · ควบคุมดูแลรายการสินค้า · Admin ปิดหรือเปิดการขายสินค้าที่ไม่เหมาะสมกลับคืนได้ พร้อมบันทึกเหตุผลไว้ทุกครั้ง เหมือนกับ ADM-001 การปิดการขายจะเปลี่ยนสถานะสินค้าเป็น SUSPENDED ซึ่งเป็นสถานะที่สงวนไว้ให้ Admin เท่านั้น — ผู้ขายเปลี่ยนออกจากสถานะนี้เองไม่ได้ (ดู PROD-002) มีเพียง Admin เท่านั้นที่เปิดการขายกลับได้ โดยระบบจะคืนสถานะเป็น ACTIVE หรือ OUT_OF_STOCK ตามจำนวนสต็อกคงเหลือ ณ ขณะนั้น การปิดการขายจะปิดกั้นคำสั่งซื้อใหม่ (ค้นหาไม่เจอในหน้าสาธารณะ เพิ่มลงตะกร้าและ checkout ไม่ได้) แต่ไม่ยกเลิกคำสั่งซื้อที่จ่ายเงินแล้ว (PAID)

## แก้ที่ 2 — PROD-002 (§4.4 แคตตาล็อกสินค้าและการจัดการสินค้า)

**เดิม**

> PROD-002 · แก้ไข/ลบสินค้าของตัวเอง · ผู้ขายแก้ไขราคา, รายละเอียด, รูปภาพ, หมวดหมู่ และสต็อกได้ในขณะที่สินค้าอยู่ในสถานะ ACTIVE หรือ INACTIVE **การลบเป็นแบบ soft-delete ไปสถานะ REMOVED** ซึ่งจะซ่อนจากการค้นหาสาธารณะ สินค้าที่ถูกอ้างอิงโดยคำสั่งซื้อที่ยังไม่ถูกยกเลิกอย่างน้อย 1 รายการ จะลบถาวรไม่ได้ ทำได้แค่ปิดการขาย เพื่อรักษาความถูกต้องของประวัติคำสั่งซื้อ

**ใหม่** — แทรกประโยคใหม่หลัง "…ACTIVE หรือ INACTIVE" ก่อน "การลบเป็นแบบ soft-delete"

> PROD-002 · แก้ไข/ลบสินค้าของตัวเอง · ผู้ขายแก้ไขราคา, รายละเอียด, รูปภาพ, หมวดหมู่ และสต็อกได้ในขณะที่สินค้าอยู่ในสถานะ ACTIVE หรือ INACTIVE และสลับสถานะระหว่าง ACTIVE กับ INACTIVE เองได้ **แต่หากสินค้าถูก Admin ระงับ (สถานะ SUSPENDED ตาม ADM-005) ผู้ขายจะแก้ไขข้อมูล เปลี่ยนสถานะ หรือ soft-delete สินค้านั้นไม่ได้เลย ทุกคำขอจะถูกปฏิเสธจนกว่า Admin จะเปิดการขายกลับให้ — ที่ต้องห้าม soft-delete ด้วย เพราะไม่เช่นนั้นผู้ขายจะเลี่ยงการระงับได้ด้วยการลบทิ้งแล้วกู้กลับมาเป็น ACTIVE** การลบเป็นแบบ soft-delete ไปสถานะ REMOVED ซึ่งจะซ่อนจากการค้นหาสาธารณะ สินค้าที่ถูกอ้างอิงโดยคำสั่งซื้อที่ยังไม่ถูกยกเลิกอย่างน้อย 1 รายการ จะลบถาวรไม่ได้ ทำได้แค่ปิดการขาย เพื่อรักษาความถูกต้องของประวัติคำสั่งซื้อ

## แก้ที่ 3 — PROD-005 (§4.4 ต่อหน้า 6) ⚠️ สำคัญที่สุด

จุดนี้พลาดง่ายที่สุด ถ้าไม่แก้ **การเติมสต็อกจะปลดการระงับของ Admin เองเงียบๆ**

**เดิม**

> **สินค้าจะเปลี่ยนเป็น OUT_OF_STOCK อัตโนมัติเมื่อสต็อกเหลือ 0 และกลับเป็น ACTIVE เมื่อเติมสต็อกมากกว่า 0**

**ใหม่**

> สินค้าจะเปลี่ยนเป็น OUT_OF_STOCK อัตโนมัติเมื่อสต็อกเหลือ 0 และกลับเป็น ACTIVE เมื่อเติมสต็อกมากกว่า 0 **ยกเว้นสินค้าที่อยู่ในสถานะ SUSPENDED (ADM-005) ซึ่งการเปลี่ยนแปลงสต็อกจะไม่เปลี่ยนสถานะให้อัตโนมัติ เพื่อไม่ให้การเติมสต็อกปลดการระงับของ Admin โดยไม่ตั้งใจ**

## แก้ที่ 4 — CART-001 (§4.5 ตะกร้าสินค้าและการชำระเงิน)

**เดิม**

> CART-001 · เพิ่มลงตะกร้า · ผู้ใช้ที่ login แล้ว ยกเว้นผู้ขายสินค้านั้นเอง สามารถเพิ่มสินค้าและจำนวนลงตะกร้าแบบถาวรของตัวเองได้ **โดยจำนวนที่เพิ่มได้ถูกจำกัดตามสต็อกปัจจุบัน**

**ใหม่**

> CART-001 · เพิ่มลงตะกร้า · ผู้ใช้ที่ login แล้ว ยกเว้นผู้ขายสินค้านั้นเอง สามารถเพิ่มสินค้าและจำนวนลงตะกร้าแบบถาวรของตัวเองได้ โดยจำนวนที่เพิ่มได้ถูกจำกัดตามสต็อกปัจจุบัน **และเพิ่มได้เฉพาะสินค้าที่สถานะ ACTIVE เท่านั้น — สินค้าที่ INACTIVE, OUT_OF_STOCK, REMOVED หรือ SUSPENDED เพิ่มลงตะกร้าไม่ได้ หากสินค้าที่อยู่ในตะกร้าอยู่แล้วเปลี่ยนไปเป็นสถานะเหล่านี้ภายหลัง จะ checkout รายการนั้นไม่ได้ (CART-004)**

## ที่ตรวจแล้วว่า **ไม่ต้องแก้**

| ข้อกำหนด | เหตุผล |
| --- | --- |
| PROD-003 ค้นหาและเรียกดู | เขียนไว้แล้วว่า "ค้นหาสินค้าสาธารณะที่สถานะ ACTIVE ได้" → `SUSPENDED` ถูกกรองออกอัตโนมัติ |
| PROD-004 รายละเอียดสินค้า | เป็นหน้าสาธารณะของสินค้าที่ ACTIVE อยู่แล้ว หากต้องการชัดขึ้นให้เพิ่มว่า "สินค้าที่ SUSPENDED เข้าหน้ารายละเอียดสาธารณะไม่ได้" |
| ADM-004 บันทึก Audit | ใช้ `DEACTIVATE_PRODUCT` / `REACTIVATE_PRODUCT` ที่มีอยู่แล้ว ไม่ต้องเพิ่มประเภทการกระทำใหม่ |
| §6 ความปลอดภัยและคุณภาพ | กฎ "บังคับใช้การตรวจสอบสิทธิ์ที่ฝั่ง server ไม่ใช่แค่ที่ UI" ครอบคลุมการบล็อกนี้อยู่แล้ว |
