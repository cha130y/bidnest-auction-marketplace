- **อ้างอิงการตัดสินใจ:** [ADR-0002](../architecture/adr/0002-admin-suspended-product-status.md)

## ที่มา

SRS v4 มีข้อกำหนด 2 ข้อที่ขัดกันเอง — ADM-005 ให้ Admin ปิดการขายสินค้าที่ไม่เหมาะสมได้ แต่ PROD-002 ก็ให้ผู้ขายสลับ `ACTIVE`/`INACTIVE` เองได้ ผลคือผู้ขายกด `ACTIVE` กลับได้ทันทีหลัง Admin สั่งปิด **ทำให้ ADM-005 ไม่มีผลบังคับจริง**

ทีมตัดสินใจแล้ว 2 ข้อ:

1. ถ้า Admin เป็นคนสั่งปิด ผู้ขายต้องเปิดกลับเองไม่ได้ → เพิ่มสถานะ `SUSPENDED` (migration `20260819031110_add_suspended_product_status`)
2. **ไม่ทำฟีเจอร์กู้คืนสินค้าที่ลบแล้วใน V1** → `REMOVED` เป็นสถานะปลายทาง ใช้ `INACTIVE` สำหรับพักขายชั่วคราวแทน

## ❌ ที่ยังต้องแก้อีก 4 จุด

### จุดที่ 1 — ADM-005 อธิบาย SUSPEND เหมือนเป็น flag แยก ไม่ใช่สถานะ ⚠️ สำคัญที่สุด

**ปัจจุบัน**

> Admin ปิด(SUSPEND) หรือเปิด(ACTIVE) การขายสินค้าที่ไม่เหมาะสมได้, กรณีที่ stock สินค้าเหลือ 0 ผู้ใช้งาน(User) ได้ทำการเติม stock ให้มากกว่า 0 (อ้างอิงจาก PROD-005) **สถานะจะไม่เปลี่ยนจาก OUT_OF_STOCK ไปเป็น ACTIVE** ถ้าสินค้านั้นถูกปิด (SUSPEND) โดย admin พร้อมบันทึกเหตุผลไว้ทุกครั้ง เหมือนกับ ADM-001 การปิดการขายจะปิดกั้นคำสั่งซื้อใหม่ แต่ไม่ยกเลิกคำสั่งซื้อที่จ่ายเงินแล้ว (PAID)

**ปัญหา** — ประโยคนี้บอกว่าสินค้าอยู่ในสถานะ `OUT_OF_STOCK` **และ** ถูก SUSPEND พร้อมกัน แต่ `products.status` เป็น field เดียวที่เก็บได้ค่าเดียว พอ Admin สั่งปิด ค่าจะเป็น `SUSPENDED` ทับ `OUT_OF_STOCK` ไปแล้ว

ถ้าปล่อยไว้ Dev 3 อาจ implement เป็น boolean แยก (`isSuspended`) ซึ่งเป็นทางเลือกที่ ADR-0002 ปฏิเสธไปแล้ว **ทำให้ schema ไม่ตรงกับ SRS**

**แก้เป็น**

> Admin ปิดการขายสินค้าที่ไม่เหมาะสมได้ โดยเปลี่ยนสถานะสินค้าเป็น SUSPENDED ซึ่งเป็นสถานะที่สงวนไว้ให้ Admin เท่านั้น ผู้ขายเปลี่ยนออกจากสถานะนี้เองไม่ได้ (ดู PROD-002) มีเพียง Admin เท่านั้นที่เปิดการขายกลับได้ โดยระบบจะคืนสถานะเป็น ACTIVE หรือ OUT_OF_STOCK ตามจำนวนสต็อกคงเหลือ ณ ขณะนั้น **ระหว่างที่สินค้าอยู่ในสถานะ SUSPENDED การที่ผู้ขายเติมสต็อกจะไม่ทำให้สถานะเปลี่ยนเป็น ACTIVE โดยอัตโนมัติ (อ้างอิงจาก PROD-005)** ทุกครั้งที่ปิดหรือเปิดต้องบันทึกเหตุผลไว้ เหมือนกับ ADM-001 การปิดการขายจะปิดกั้นคำสั่งซื้อใหม่ (ค้นหาไม่เจอในหน้าสาธารณะ เพิ่มลงตะกร้าและ checkout ไม่ได้) แต่ไม่ยกเลิกคำสั่งซื้อที่จ่ายเงินแล้ว (PAID)

*ข้อความใหม่นี้รวมจุดที่ 2 ไว้แล้ว*

### จุดที่ 2 — ADM-005 เขียนว่าเปิดกลับเป็น `ACTIVE` อย่างเดียว

ADR-0002 กำหนดว่าเปิดกลับต้องคืนเป็น `ACTIVE` **หรือ** `OUT_OF_STOCK` ตามสต็อก ณ ขณะนั้น ถ้าเขียนแค่ `ACTIVE` แล้ว Admin ปลดตอนสต็อกเหลือ 0 จะได้สินค้า `ACTIVE` ที่ไม่มีของ ขัดกับ PROD-005

→ แก้ไปพร้อมกับจุดที่ 1 แล้ว

### จุดที่ 3 — §5.1 คำสั่งถูก paste ทิ้งไว้ ยังไม่ได้แก้ในลิสต์จริง

**ปัจจุบัน**

> …shipments, shipment_events; **สถานะสินค้า ACTIVE/INACTIVE/OUT_OF_STOCK/REMOVED**; สถานะออเดอร์ PENDING/PAID/CANCELLED; สถานะการจัดส่ง PROCESSING/SHIPPED/IN_TRANSIT/DELIVERED/CANCELLED; **เพิ่ม SUSPENDED ในลิสต์สถานะสินค้า**

ข้อความท้ายบรรทัดคือ *คำสั่ง* จาก change request ฉบับก่อนที่ถูก copy ลงไปตรงๆ แต่ลิสต์จริงยังมี 4 ค่าเหมือนเดิม

**แก้เป็น**

> …shipments, shipment_events; **สถานะสินค้า ACTIVE/INACTIVE/OUT_OF_STOCK/REMOVED/SUSPENDED (SUSPENDED สงวนไว้ให้ ADM-005 เท่านั้น ผู้ขายเปลี่ยนออกเองไม่ได้)**; สถานะออเดอร์ PENDING/PAID/CANCELLED; สถานะการจัดส่ง PROCESSING/SHIPPED/IN_TRANSIT/DELIVERED/CANCELLED

แล้ว **ลบ** ข้อความ "เพิ่ม SUSPENDED ในลิสต์สถานะสินค้า" ท้ายบรรทัดทิ้ง

### จุดที่ 4 — PROD-002 วงเล็บอ้างถึงฟีเจอร์ที่ไม่มี และยังไม่ระบุว่า `REMOVED` กู้คืนไม่ได้

**ปัจจุบัน**

> …เพื่อรักษาความถูกต้องของประวัติคำสั่งซื้อ, สินค้า SUSPENDED ผู้ขายแก้ไข/เปลี่ยนสถานะ/soft-delete ไม่ได้ **(กันเลี่ยงด้วยการลบแล้วกู้กลับ)**

**ปัญหา 2 อย่าง**

1. V1 ไม่มีฟีเจอร์กู้คืน วงเล็บนี้จึงอ้างถึงสิ่งที่ไม่มีอยู่จริง เหตุผลที่แท้จริงคือการย้ายไป `REMOVED` จะลบร่องรอยว่าถูกระงับ ทำให้ guard ในขั้นถัดไปตรวจไม่เจอ
2. ยังไม่มีข้อความบอกว่า `REMOVED` กู้คืนไม่ได้ ซึ่งเป็นสิ่งที่ทีมเพิ่งตัดสินใจ

**แก้เป็น**

> …เพื่อรักษาความถูกต้องของประวัติคำสั่งซื้อ สินค้าที่อยู่ในสถานะ SUSPENDED ผู้ขายแก้ไข เปลี่ยนสถานะ หรือ soft-delete ไม่ได้ ทุกคำขอจะถูกปฏิเสธจนกว่า Admin จะเปิดการขายกลับให้ (ที่ต้องห้าม soft-delete ด้วย เพราะการย้ายไป REMOVED จะลบร่องรอยว่าสินค้าเคยถูกระงับ ทำให้การตรวจสอบในขั้นถัดไปไม่เจอ) **สถานะ REMOVED เป็นสถานะปลายทาง ไม่มีการกู้คืนใน V1 — หากผู้ขายต้องการเพียงหยุดขายชั่วคราว ให้ใช้ INACTIVE แทน ซึ่งเปิดกลับเองได้ตลอด**

## ที่ตรวจแล้วว่า **ไม่ต้องแก้**

| ข้อกำหนด | เหตุผล |
| --- | --- |
